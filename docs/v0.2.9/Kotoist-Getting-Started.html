Getting Started

Kotoist is a Koto-based MIDI sequencer in a VST3 plugin, with a separate Windows command-line tool that exports Standard MIDI Files.

Quick start

Paste this working starter line into the editor:

midiout({degree: 0}, 0)

Click Run, then start playback in your host. This pattern follows the host transport; it does not trigger just because you hold a MIDI key.

Kotoist sends MIDI, not audio

The plugin generates MIDI events. To hear them, route Kotoist’s MIDI output to a software instrument or external MIDI destination in the host. The receiving instrument makes the sound.

A lit MIDI OUT indicator means Kotoist recently sent a note-on event to the host. It does not prove that a downstream instrument received it or produced sound.

Using the VST3

  1. Unzip kotoist-windows-vst3-v0.2.9 and place the .vst3 bundle in a VST3 folder that your host scans.
  2. Rescan plugins in the host and add Dexter U.S. Kotoist to a MIDI-capable track.
  3. Enter a Koto script and press Run. Start the host transport to play sequenced patterns.
  4. Route the plugin’s MIDI output to an instrument track or other MIDI destination. Kotoist itself does not generate audio.

The MIDI OUT indicator

MIDI OUT ● briefly turns green when Kotoist dispatches a note-on event. It is a send-side check only; confirm host routing and the receiving instrument separately.

Load and save scripts

Use the editor’s Load and Save buttons for .koto files. On Windows, scripts are stored in the plugin bundle’s Dexter U.S. Kotoist/Scripts subfolder. If Windows blocks writes because the plugin is under Program Files, move the bundle to a user-writable VST3 folder.

Windows command-line MIDI exporter

The CLI uses the same Koto interpreter and pattern scheduler as the VST3, but renders a MIDI file instead of sending live MIDI to a host. It does not render audio.

1. Make a Koto script

Create a plain-text file named test.koto containing:

midiout({degree: 0}, 0)

2. Export a Standard MIDI File

Open Command Prompt in the folder containing kotoist.exe and your script, then run:

kotoist.exe midi "test.koto" "test.mid" --bpm 120 --bars 4

Open test.mid in a DAW or MIDI editor, then route it to an instrument to hear it.

OptionMeaningDefault / limits
--bpm 120Tempo for the export.Default 120; range 1–1000 BPM.
--bars 4Number of 4/4 bars to render.Default 4; range 1–256 bars.
midi --helpPrints command usage.One export is limited to 10 minutes.

If the script produces no MIDI notes, the CLI reports an error instead of writing a silent file.

How long will the MIDI be?

There is no --seconds option. The CLI exports whole 4/4 bars, so use seconds = bars × 4 × 60 ÷ BPM. At 120 BPM, 4 bars is about 8 seconds and 8 bars is about 16 seconds; at 60 BPM, 2 bars is about 8 seconds. This is a whole-bar approximation.

If you see no MIDI or hear no sound

  • For the VST3 pattern above, press Run and start the host transport.
  • Check that the host track receives MIDI from Kotoist and that a synth/instrument is routed after it.
  • Watch for the green MIDI OUT pulse. If it flashes but there is no sound, check host routing and instrument output.
  • For CLI, confirm the script contains a midiout pattern and the output .mid contains notes.
  • The starter pattern is a sequencer pattern, not “play a note whenever I hold a key.” That behavior requires a script designed to respond to MIDI input.
